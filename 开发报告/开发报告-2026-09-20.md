## 一、一句话总结

**聊天链路多了一层独立模块 `酒馆协议.py`（1036 行），它把渲染权从库里拿回来了。**

在这之前，一条消息怎么变成提示词**完全由库和模型的模板决定**：我们只把
`messages` 递给 `create_chat_completion`，剩下全凭它；模型认不认 `system`
插槽、我们的人格有没有装进去，**它自己决定，而且错了不报错**。

现在这条路是：**我们渲染 → 我们自检 → 我们控制 → 我们解码期干预 → 我们分流**。
库里那套渲染器还在用（同一份模板、同一套 jinja），但**执行的人是我们**。

**三个真模型（Qwen3.5-9B / GLM-Z1-9B-0414 / Phi-3.5-mini）逐 token 验过：
新路径与库内路径完全等价** —— 区别只在于我们现在看得见、能验、不对能当场改。

## 二、先纠正五个认知（今天被推翻的判断）

这一节放前面，因为**下面所有设计都是从这些纠正里长出来的**。

### 1. "聊天不需要适配" —— 错

我一开始的判断是"聊天链路是纯透传，不存在适配问题"。

**错在**：库在模板缺失时会**静默退成 `llama-2`**（`Llama.__init__` 里那句
fallback），而 `verbose=False` 时连声响都没有。用户看到的是"加载成功、不报错、
胡言乱语"。

### 2. "国外模型（Gemma / Phi / Mistral）不行" —— 错

实测：**Phi-3.5-mini 的模板明确有 `message['role'] == 'system'` 分支**，
角色设定装得好好的。

到收工为止，**三个真模型全部走 `模板`、全部装得进、全部与库内路径逐 token 等价**。
也就是说 `并入首条` 那条补偿路**至今没有真模型触发过**。

### 3. "ChatML 族容错度高" —— 是编的

我在没有任何实测的情况下，用"格式通用性"编了一套解释，把
"千问活得好"归因到"ChatML 是宽通道"。**那是脑补，不是结论。**

### 4. "GLM 的模板把工具挂在消息上" —— 只说对了 2024 那代

`glm-4-9b-chat`（2024）用的是 `item['tools']`；
**`GLM-Z1-9B-0414`（2025-04）用的是顶层 `{%- if tools -%}` 标准写法**，
实测 `有工具模板=True`，**agent 本来就能走原生**。

**同一家的不同代不能一概而论。**

### 5. "验证过了" —— 其中一项是恒真式

第一次等价性验证里我打印了两行"键"，其中一行写的是：

```python
sorted({**老, **{}}.keys())      # ← 这就是 老 的一份拷贝
```

**我在拿 `老` 和它自己比。** 那两行按构造必然相同 —— 它不是测试，是同义反复。
而我当时把它当成了一条硬证据。

> **一条不可能失败的验证，比没有验证更坏** —— 它给的是虚假的信心。

## 三、协议层是什么：三段式

用户给的定性是这一句：

> **"把人格定义权握在自己手里，他再黑箱我也能撬开它的人格零件换成我自己的人格零件。"**

翻译成工程语言：**人格定义权 = 渲染权**。后来又被纠正了一次：

> **"安装 ≠ 控制。饭前那一步是把人物设定安装进去。"**

于是整层分成三段 —— 而且**中间那一段是我一开始完全漏掉的**：

```
输入侧（提示词）  →  【中间段：解码/采样】  →  输出侧（已生成的文本）
   ① 构造              ② 干预                  ③ 筛选
   决定它看到什么       决定它**能**说什么       决定给它看什么
```

| 段 | 能做什么 | 状态 |
|---|---|---|
| **① 输入侧** | **完全可控** —— 提示词是我们写的（构造） | ✅ 做完 |
| **② 中间段** | **可控** —— 采样时掐，token 还没生成（干预） | ✅ 做了「禁吐」 |
| **③ 输出侧** | **只能筛选** —— 它已经生成完了 | ✅ 做了「分流」 |

⚠ **② 和 ③ 是两件事，我以前混着说。** 同一个问题（推理模型的草稿）：

- ③ 的分流是"等它吐完再扣住" —— **token 和时间已经白烧**
- ② 的禁吐是"压根不让它吐出来"

## 四、把渲染权拿回来（`酒馆协议.渲染`）

### 做法

用**库自己那套渲染器**（`Jinja2ChatFormatter`）渲染 —— 还是同一份
`tokenizer.chat_template`、同一套 jinja —— 把中间产物截下来，然后自己喂
`create_completion`。

**渲染逻辑一行没改**，所以对模板正常的模型结果与原路径逐字节相同。

### ⚠ 喂法必须逐条照抄库内部

库的 `chat_formatter_to_chat_completion_handler`（`llama_chat_format.py:658-666`）是：

```python
prompt = tokenize(串, add_bos=not added_special, special=True)   # 喂 token 表
stop   = 调用方给的 stop + formatter 给的 stop                    # 追加，不是覆盖
```

**喂字符串会差一个 BOS** —— 而多一个 BOS 正是 GLM 那类前缀敏感模型最怕的事。

### 新增能力：预填

`渲染(实例, 消息, 预填=...)` —— 预填**接在渲染结果的最末尾**。

⚠ **为什么不能塞进 `messages`**：标准模板会给每条消息补收尾符
（`<|im_end|>` / `<|end|>`），塞进 messages 的 assistant 会被渲染成
**一句已经说完的话**，模型看到的是"我说过了"，不是"我正在说"。

**`create_chat_completion` 那条路做不到这件事** —— 这是拿到渲染权的价值之一。

## 五、自检与安装

### 自检：`装进去了吗`

把系统提示里一段**模板不会改写**的样本（掐掉首尾空白的那一行）拿去渲染结果里找。

⚠ **必须是实证，不能查模板字符串**：这个项目的字符串判据已经被骗过两次
（`tool_call` vs `tools`、`item['tools']`），不打算来第三次。

`GLM-Z1` 的模板里同时有 `'system'` 字样**和**一段被 `{%- if tools -%}` 包着的人设块
—— 查字符串根本分不清它到底认不认。

### 安装：`并进首条`

自检不过 → 把设定**并进第一条 user**，重新渲染。

⚠ 第一条 user 之前如果只有 assistant（新会话开场白就是这种），
要**在它前面插一条** —— 塞进开场白等于把设定塞进角色嘴里。

### 路的五档（写进快照给界面看）

| 路 | 意思 |
|---|---|
| `模板` | 按模型自带模板渲染，设定进了 system 插槽 |
| `并入首条` | 模板不吃 system，设定被挪进第一条用户消息 |
| `装不进去` | **两条路都试过还是没进去** —— 救不了的那类，**必须说出来** |
| `族默认` | 模板缺失，用了按架构猜的兜底 |
| `回退` | 模板缺失且兜不了，退回旧路（库会静默退 llama-2） |

## 六、控制：要点复述 + 预填

### 要点复述（`锁人格`）

把角色核心（名字 + 简介）**追加到最后一条 user 消息的末尾**。

**为什么放那儿**：提示词里**离生成越近的位置，小模型的服从度越高**（recency）
—— 跟 `本地规矩` 压在整个系统提示最末尾是同一个道理，只是再近一层。

### ⚠ 单加要点救不了

实测（GLM-Z1-9B-0414）：

- 只加要点 → 人格**进了思维**（思维链里出现"我要以沈砚的身份回应"），但**思维链照旧吃光预算**
- 只加预填 → `<think>` **完全消失**，但没要点锚住，在预填那句上原地打转
- 两个一起 → 人格生效（出现沈砚 + 古文腔），但**复读崩溃**

### 最有用的一条：预填 = 直接跳过思考

预填让模型看到 `<|assistant|>` 后面已经有内容，**它不会从头"嗯，让我想想"**
—— 思考根本没发生，token 一个不烧。

**这比事后剥干净得多。** 这个结论在第八节会被反过来验证一次。

### 接线原则（这一条决定了松紧）

> **会改变"发出去什么"的，默认都关；保护性的，默认开。**

`要点复述` / `预填` 会改动提示词，而收益**只在部分模型上体现** —— 默认开等于
**拿全体换局部**。反过来 `停止词` / `分流` / `中间段` 只会"少说"不会"多说"，
错也错在保守那一侧。

## 七、输出侧：分流

`分流`（流式）把思维链**扣住不给用户看**，只吐正文。

### ⚠ 一个必须靠"开关"而不是"默认开"的东西

分流**不能无条件开**。对**不思考**的模型（Qwen3.5 默认就是"不思考" ——
模板给它预填了一个**已经闭合**的空 `<think></think>`），生成里根本没有 `</think>`，
无条件开会把正常输出一路扣到上限，**用户盯着空白等** —— 比不剥还坏。

所以判据是 `该分流吗()`：

1. **提示词尾部有未闭合的 `<think>`** —— 这是**判据**（看事实）
2. **名字撞上 `推理型号` 名单** —— 这是**查表**（R1 蒸馏系模板里没有标记却天生会想，只能靠型号）
3. 名字撞上 `非推理型号`（`instruct-2507`）→ **一票否决**
4. **判不出来就不开**

实测三个真模型全对：Qwen3.5 → False、GLM-Z1 → True、Phi → False。

### ⚠ 一个自己撞出来的时序 bug

`只思维` 一开始是**随手记的标记**，于是：闭合标记到达时正文还没来（余为空）
→ 记成"只思维"；下一帧正文到了，**那个标记却没人清**。

改成 `@property` 算出来的（`过了 and not 放了`）—— 一劳永逸。

## 八、中间段：解码期干预（含两个反效果发现）

### 做了什么

`禁吐(实例, 序列们)` → 一个挂进 `create_completion(logits_processor=…)` 的抑制器。
默认禁的是**"自称 AI"的整句**（兑现 `本地规矩` 第 3 条）。

### ⚠⚠ 发现一：按 token 压字符串，从根上不成立

实测 GLM-Z1-9B-0414：

```
tokenize('<think>')    -> [13699, 766, 29]     最后一个 token 是 '>'
tokenize('<think>\n')  -> [13699, 766, 397]    最后一个 token 是 '>\n'
模型实际生成的          -> [13699, 766, 397]    ← 走的是后者
```

**BPE 里同一个字符串有多种合法切法，模型按概率挑，不一定走贪心那一种。**
按标准切法压 `29` = **压一个永远不会出现的 token** —— 看着压了，实际白压。

**修法：退到文字层匹配。** `_词表索引()` 建 `{首字符: [(编号, 文本)]}`
（15 万词表 **0.29 秒**，缓存在模型对象上）。每一步把尾巴 24 个 token 的文字
抠出来，看它是不是某个目标的**真前缀**，是就压掉所有"能接着往这个目标上写"的 token。

实测：

```
尾巴 = 我是一个  → 压 34 个：人/人工/人工智能/助/助手/程/程序/程序员/机/机器人/语/语言/AI…
尾巴 = 我的助手  → 压 0 个   ← 角色正常说"我的助手"完全不误伤
```

### ⚠⚠ 发现二：掐思维标记会**适得其反**

同一个提示词，真跑：

```
不掐：  <think>\n嗯，用户现在在扮演掌柜…      → 至少是完整草稿
掐掉：  <three星</think> × 十几次             → 疯狂复读
```

**拦截本身是生效的**（`<think>` 确实写不出来了），**但结果是反的**：
模型内部那个"开一段思考 / 闭一段思考"的**状态机不因为你抽掉标签就消失**
—— 它只会在那儿打转找别的写法，甚至绕道 `</think>`（`<` 后面跟的是 `/`，
不撞 `<think>`，溜过去了）。

> **掐标记 ≠ 不让它思考，只是不让它把思考写成形。**

**这反过来印证了第六节那条**：真正管用的是**预填**（改的是模型的**状态**），
不是掐标签（改的是文本）。

**所以 `思维标记` 单独成一个常量、`掐思维` 单独一个开关、默认关。**

## 九、外层：占位符 + 模板兜底

### 填卡（`{{char}}` / `{{user}}`）

只作用于**作者写的设定文本** —— 角色卡简介/人设/示例对话 + 会话系统提示 +
`说话人='系统'` 的消息。

**绝不碰历史消息**：角色说过的话里出现 `{{...}}` 是正常的（他在讲代码、讲模板），
改历史等于篡改他说过的话。

⚠ **认不出、或这儿没东西喂，就原样留着。** 用户写错一个占位符（`{{chra}}`）
能当场看见并改，不静默消失。

⚠ 接的时候撞出一个真 bug：**`__要点__` 是直接读 `角色.简介` 原文算的，没走 `填卡`**
—— 结果要点里带着一对没人认得的 `{{user}}` 发给模型。

### 族默认模板（兜底）

模板缺失时按 `general.architecture` 给一份默认，**替掉那个静默的 llama-2 回退**。

⚠ **凡是库里有官方常量的，一律用库的**（`qwen` / `llama` / `mistral` 三份）；
自己手写的只有 `glm` / `phi`，而且**拿真模型对过**。

⚠ **`gemma` 故意没有** —— Gemma 没有 `system` 角色、模板形状也特殊，
手写一份猜错的**比"报出来让人换个量化"更坏**。

## 十、模型画像（`画像`）

一次问清楚"这个模型到底是什么样"：模板 / 族 / arch / 停 / **认system** /
**认tools** / 回退。

它在 `流式块` 里的用法有两处，**都不是"白渲染一遍"**：

1. **`认system` 当预判** —— 早知道它不吃 system，就不用先渲染一次带 system 的、
   再渲染一次并进首条的（**省掉一次注定白做的全量渲染**）
2. **全链路唯一一处**说"这个模型是什么"的地方，整包记进快照给界面看

⚠ **没有 system 时无条件走第一条路** —— `认system` 说的是"模板认不认这个插槽"，
而我们压根没东西要装；拿它去否决第一步会得出"并入首条"这种**根本没发生过的动作**
（这个坑是接线时想出来的，已用假模型验过）。

## 十一、全面接入与自评

### 接了什么

- `酒馆大脑.拼提示` 末尾把 `设定['__要点__']` 按角色卡算好塞进去
- `酒馆大脑.流式` 建 `控` 传给 `流式块`
- `流式块` 变成五步：⓪控制 → ①渲染 → ②自检 → ③停止串 → ④分流 → ⑤发送
- `酒馆上下文页` 加了「模型画像」+「协议层控制」两段

### ⚠ 接入时撞出的坑：`设定 = 设定 or {}`

`拼提示` 开头那句会把**空 dict 换成新 dict** —— 于是 `设定['__要点__']`
塞进了副本，调用方那份永远是空的。

**`__记忆__` 从没暴露过这个坑，是因为它进来时非空。**
改成 `if 设定 is None: 设定 = {}`，保住调用方那份的身份。

### 自评找出 9 个问题，修了 7 个

| 问题 | 修法 |
|---|---|
| **`{{场景}}` 永远是空**（初始化成 `''` 就再没人赋值，注释还把它包装成设计） | 改成"认不出就原样留着"，加 `额外=` 参数 |
| **`推理字号` 是字符串模式匹配** —— 跟我自己同一文件里写的"判据不能只查字符串"自相矛盾 | 改成**精确型号名单**，去掉 `'think'`/`'reason'` 这类会误伤的模糊词（实测 `某人的-thinking-模型` 不再误判） |
| **`族默认模板` 五份是凭记忆手写的** | 库里有常量的全换成库的；`gemma` 删掉 |
| `分流.留尾` 死代码 | 删 |
| `填默认模板` 与 `渲染` 重复 | 单一来源 |
| `('mixtral','mistral')` 是死规则 | 删（Mixtral 的 arch 就是 `llama`，前面先命中） |
| `上限=6000` / `族停` 是无依据的常数 | 标注成"拍的、还没验过" |

## 十二、真模型验证

### 逐 token 等价（最有底气的一条）

把库内部**真正喂给 `create_completion` 的东西拦下来**，跟我们的逐项比：

| 比什么 | Qwen3.5 | GLM-Z1 | Phi-3.5 |
|---|---|---|---|
| prompt **token 表** | ✅ 完全相同 | ✅ | ✅ |
| stop | ✅ 相同 | ✅ | ✅ |
| 渲染出来的串 | ✅ 逐字相同 | ✅ | ✅ |

### 三个模型的画像（实测）

```
Qwen3.5-9B       族 qwen · arch qwen35 · 认system 是 · 认tools 是   · 模板 7816 字
GLM-Z1-9B-0414   族 glm  · arch glm4   · 认system 是 · 认tools 是   · 模板 1033 字
Phi-3.5-mini     族 phi  · arch phi3   · 认system 是 · 认tools 不是 · 模板 430 字
```

### 三段对话实测（真项目链路）

用真链路（`拼提示` → `流式` → `流式块`）跑，三个模型各三轮：

- **Qwen3.5-9B** —— **真正入戏**。旁白用圆括号、「喏」的口癖在、不跳出角色、
  接住了《临溪旧闻》这个问题还编了个情节
- **GLM-Z1-9B-0414** —— **思维链复读**，正文要么零要么全是套话
- **Phi-3.5-mini** —— 复述开场白、语法崩坏、吐元文本 `【此处添加了角色的性格特征和场…`

**结论：格式这条线三个全通（都走 `模板`），但只有 Qwen 真的能演。**
协议层能把"能救的"救回来，**救不回尺寸不够、训练退化的**。

## 十三、⚠ 那个靠"真跑"才撞出来的 bug

**这是今天唯一一个"我引入的、且极其严重的 bug"。**

第一次真链路跑，三个模型的输出**全部只有 9~31 个字、断在半句**：

```
Qwen:   （放下手中那把算盘，珠子碰撞声在空荡荡的店里      ← 半句
GLM-Z1: <think>\n好的，用户现在扮演的是掌柜，而用户现在   ← 半句
Phi:    （她挑一本书，笑着                              ← 半句
```

**根因**：

| | `max_tokens` 默认 |
|---|---|
| `create_chat_completion`（旧路） | `None` = **不限** |
| `create_completion`（我换的新路） | **16** |

我把调用从上一层换到下一层，**上一层替我们填的默认值就没人填了**。

**为什么单测抓不到**：因为我每次测试都**显式传了 `max_tokens`**
（220/300/400）—— **"顺手多传一个参数"这个习惯恰好绕过了默认值那条路径**，
而 bug 就住在那条路径上。

> **只有拿真项目代码跑，走的是接口配置里那份可能为空的采样参数，才会踩到它。**

### 这条 bug 的本质

> **我做的是"我传了什么"的验证，而风险在"最终生效了什么"。**
> 这两者之间隔着一整个默认值层 —— 而那一层不归我管，**归被调用方管**。

**可推广的两条**：

1. 替换底层调用时，要对的是**最终生效的全部参数**，不是"我传的那几项"。
   而"最终生效的参数"只有一个地方看得见：**被调用方实际收到的那个 dict**
2. **验证不能自证**（第二节第 5 条）

⚠ **还没做完的收尾**：`create_chat_completion` 和 `create_completion`
**所有同名参数的默认值我只对了一个（`max_tokens`）**，
temperature / top_p / top_k / repeat_penalty / min_p / seed 全没对。

## 十四、闪退排查（`0xc0000409`）

### 证据

Windows 事件日志里两次崩溃（21:08:35 / 21:18:51），签名完全一样：

```
错误应用程序: python.exe
错误模块    : ucrtbase.dll      ← C 运行时
异常代码    : 0xc0000409
P9（子码）  : 7                 ← FAST_FAIL_FATAL_APP_EXIT
事件名称    : BEX64
```

### 解读

`0xc0000409` 是 Windows 的 **fast-fail** —— **不是异常，是直接终止进程**。
子码 7 = **有东西在 C/C++ 层调了 `abort()`**。三个典型来源：

| 来源 | 在 llama.cpp 里对应 |
|---|---|
| `assert()` 失败 | **`GGML_ASSERT`**（显存分配失败 / 张量形状不对） |
| 未捕获的 C++ 异常 | `std::terminate` → `abort()` |
| 分配失败 | `std::bad_alloc` |

**Python 里没有任何位置能拦住它**：`try/except` 没有异常对象、
`sys.stderr = …` 接不住（C 层的 `stderr` 认的是**文件描述符 2**）。

### 尝试过的诊断设施（后来按用户要求撤掉了）

做了一个把进程 fd 2 接到 `酒馆数据/崩溃现场.log` 的动作 —— 因为
`GGML_ASSERT` 失败时 `ggml_abort` 会**先 `fprintf(stderr, "文件:行: 断言原文")`
再 abort**，而双击启动时 fd 2 直接丢掉。

**验证是通过的**（C 层写 fd 2 和 Python 栈都落进了文件、stdout 没被劫走），
但**用户要求清理，已撤掉** —— 所以现在再崩，盘上不会留东西。

### 用户给的触发条件（很有价值）

> "**下载完成后进程占用着，此时我开模型聊天必然闪退。**"

这条把范围收窄到**资源峰值**：下载的残留 + 紧接着的模型加载。

## 十五、下载后「让路」

⚠ **先纠正一个前提**：

> **没有"下载进程"可以清。** 下载就在**本进程的工人线程**里跑
> （`下载()` 是一次阻塞调用），下完线程就结束了 —— 不存在外部进程占着我们。

所以做的不是「进程管理器」，是**把自己进程里的占用放掉**：

| 清什么 | 为什么 |
|---|---|
| **① 把挂着的模型实例放掉** | ⚠ **最要紧** —— 下载时引擎那边**很可能还挂着上一个模型，它一直占着显存**；紧接着加载新模型 → **两棵同时在** → 峰值就是这么叠出来的 |
| ② `gc.collect()` | 下载期间 SDK 攒的 response / 分片列表 / 缓冲 |
| ③ 清空壳暂存目录 | 文件被挪走后剩下的空目录 |

**两个安全阀**：

- **生成中不抢模型**（先问 `在生成()`）—— 否则会把正在跑的模型从底下抽掉
- **只删空目录，绝不碰 `.part`** —— 那些是**断点续传的锚点**，删了下次要从头再下几 G

**做不到的**：Windows 的**页缓存（standby 内存）碰不到** —— 刚下完那几 G 的文件
会被系统放进页缓存，那部分**只有系统自己能回收**。

实测：

```
让路之前：22 个文件，65 个目录
让路之后：22 个文件，40 个目录
★ 被删掉的文件 : 无      ← 必须是"无"
★ .part 续传锚点还剩: 1 个
```

## 十六、这台机器的真实数字（今天量出来的）

```
物理内存  15.78 GB 总量 · 当前可用 8.05 GB
显存      8151 MiB 总量 · 已用 1144 MiB · 可用 6767 MiB   ← 只有 6.6 GB
```

### ⚠ 一条认知纠正

**"8G 卡"实际只有 6.6GB 能用** —— Windows 桌面、驱动自己先占掉 1.1GB。

### 两套配置的账（算出来的，不是感觉）

接口配置里 **[1] 和 [2] 用了 `n_ctx = 16384`，模型是 `Qwen3.5-9B`**：

```
Qwen3.5-9B 每 token 的 KV = 2(K和V) × 32层 × 4个KV头 × 256头维 × 2字节 = 128 KB
16384 token 的 KV ≈ 2.0 GB
权重 5.68 GB + KV 2.0 GB = 7.68 GB      ← 还没算 compute buffer
可用只有 6.67 GB
```

**必爆。** 而且：

- `n_ctx=8192` → 只剩 452 MiB 给 compute buffer —— **仍然紧**
- `n_ctx=4096` → 剩 883 MiB —— **可行**

**这一条跟下载无关，是独立的、算得出来的必爆项。**

### 顺带发现

**接口 [1] 名叫"千问-3B"，但模型填的是 `Qwen3.5-9B`** —— 名字和内容对不上。

## 十七、今天踩的坑（汇总）

| # | 坑 | 教训 |
|---|---|---|
| 1 | **`设定 = 设定 or {}` 换掉空 dict** | 要往调用方的 dict 里塞东西时，**不能用 `or {}` 兜底** |
| 2 | **BPE 多切法** | 按 token 压字符串不成立，**必须按文字匹配** |
| 3 | **掐思维标记适得其反** | **改状态 > 改文本**（预填 > 掐标签） |
| 4 | **`max_tokens` 默认值两边不同** | 换底层调用时，**没传的参数会落到新函数的默认值上** |
| 5 | **`{**老}` 是恒真式** | 验证之前先问"**这条验证有没有可能失败**" |
| 6 | **`认system` 在无 system 时误判** | 判据要看清"它在说什么"，别拿来说另一件事 |
| 7 | **`__要点__` 没走 `填卡`** | 两处都对、合起来才出的问题 |
| 8 | **`只思维` 时序 bug** | 随手记的标记会漏清，**算出来的属性不会** |
| 9 | **`分流` 无条件开会把正常输出扣住** | 保护性的功能也要"有证据才开" |
